# Backlog projektu Calisia - 7 sprintów

## Założenia
Sprint 1 – Fundamenty projektu i architektura
Cel: przygotowanie środowiska i architektury aplikacji.

Historyjki:
S1-01 Jako zespół chcemy przygotować strukturę backendu, aby rozwijać system modułowo.
S1-02 Jako zespół chcemy przygotować podstawowy frontend, aby rozpocząć budowę UI.
S1-03 Jako zespół chcemy skonfigurować API, aby aplikacja miała punkt startowy.
S1-04 Jako zespół chcemy przygotować bazę danych i model ERD.
S1-05 Jako zespół chcemy przygotować dokumentację uruchomieniową projektu.

Sprint 2 – Rejestracja użytkownika
Cel: umożliwienie założenia konta.

Historyjki:
S2-01 Jako użytkownik chcę zarejestrować konto, aby korzystać z aplikacji.
S2-02 Jako system chcę walidować dane użytkownika, aby uniknąć błędów.
S2-03 Jako system chcę bezpiecznie przechowywać hasła.
S2-04 Jako zespół chcemy udostępnić API rejestracji.
S2-05 Jako zespół chcemy pokryć rejestrację testami.

Sprint 3 – Logowanie i bezpieczeństwo
Cel: zapewnienie autoryzacji.

Historyjki:
S3-01 Jako użytkownik chcę zalogować się do systemu.
S3-02 Jako system chcę generować token sesji / JWT.
S3-03 Jako system chcę chronić endpointy przed nieautoryzowanym dostępem.
S3-04 Jako system chcę logować próby logowania.
S3-05 Jako zespół chcemy przetestować logowanie i bezpieczeństwo.

Sprint 4 – Konto osobiste i dashboard
Cel: prezentacja danych użytkownika.

Historyjki:
S4-01 Jako użytkownik chcę widzieć saldo konta.
S4-02 Jako użytkownik chcę widzieć historię operacji.
S4-03 Jako system chcę przygotować model odczytowy dashboardu.
S4-04 Jako zespół chcemy udostępnić dashboard przez API.
S4-05 Jako zespół chcemy pokryć dashboard testami.

Sprint 5 – Przelewy
Cel: realizacja przelewów.

Historyjki:
S5-01 Jako użytkownik chcę wykonać przelew.
S5-02 Jako system chcę walidować saldo przed przelewem.
S5-03 Jako system chcę zapisać historię przelewów.
S5-04 Jako zespół chcemy udostępnić API przelewów.
S5-05 Jako zespół chcemy pokryć przelewy testami.

Sprint 6 – Historia transakcji i poprawki
Cel: ulepszenie historii i jakości systemu.

Historyjki:
S6-01 Jako użytkownik chcę filtrować historię transakcji.
S6-02 Jako użytkownik chcę sortować historię transakcji.
S6-03 Jako użytkownik chcę widzieć szczegóły transakcji.
S6-04 Jako zespół chcemy zoptymalizować bazę danych i zapytania.
S6-05 Jako zespół chcemy poprawić UI/UX i stabilność.

Sprint 7 – Frontend, integracja i stabilizacja
Cel: końcowa integracja i oddanie projektu.

Historyjki:
S7-01 Jako użytkownik chcę korzystać z aplikacji przez UI.
S7-02 Jako użytkownik chcę wykonać rejestrację i logowanie z poziomu UI.
S7-03 Jako użytkownik chcę korzystać z dashboardu i przelewów z poziomu UI.
S7-04 Jako zespół chcemy wykonać testy integracyjne i end-to-end.
S7-05 Jako zespół chcemy wdrożyć aplikację i przygotować prezentację.

**Suma sprintu: 50 SP**
